# Portable Pre-Meeting Intel

> 在第一次见面前，快速研究一个人最近正在做什么、说什么，以及外界如何理解他。

一个面向 Codex 和 Claude Code 的会前人物情报 Skill。它从公开来源中提取最近信号，建立本人叙事与外部叙事的对照，并生成一份可以直接带进会议的简报。

## 它做什么

一次调用完成四路研究：

1. **本人表达**：近期文章、访谈、播客、演讲、社交媒体和产品动作；
2. **社群反应**：行业社区、论坛、回复和讨论中的真实反应；
3. **第三方视角**：媒体、分析师、行业评论和专业机构如何描述这个人；
4. **官方身份**：官网、雇主页面、个人简介、LinkedIn 和会议资料中的身份锚点。

它重点寻找的不是一份旧简历，而是：

- 这个人在最近 90 天最重要的叙事主线；
- 他希望别人相信什么；
- 他正在建设、推动、改变或挑战什么；
- 本人如何描述自己，外界又如何理解他；
- 你在会面中可以自然提出的具体问题。

## 怎么用

```text
/portable-pre-meeting-intel [姓名] [可选：公司 / 角色 / 会面目的]
```

例如：

```text
/portable-pre-meeting-intel Patrick Collison Stripe 评估跨境支付合作
```

也可以直接用自然语言：

```text
准备我和 Rory Sutherland 的会面，重点了解他最近对行为营销和品牌增长的看法。
```

默认研究最近 **90 天**。如果用户指定“最近 30 天”“最近半年”等时间范围，则以用户指定的范围为准。

## 研究流程

```text
Step 0      解析姓名、上下文和信号窗口（默认 90 天）
Step 0.5    身份预检：确认官网、公司、LinkedIn 和公开账号
Step 1      四路并行研究
            ├─ A. 社群讨论
            ├─ B. 本人近期表达
            ├─ C. 第三方媒体与行业评论
            └─ D. 官方身份与自我描述

Step 1.5    可选的信源增强
            └─ 在可用的运行环境中，将社交账号主页升级为真实内容链接

Step 2      合成当前叙事，完成自述 vs 外界对照
Step 3      输出 Markdown 会前简报；如环境支持，也可继续生成文档
```

## 产出什么

一份适合会前 10–15 分钟阅读的六段式简报：

1. **顶部身份卡 + 全文锚句**；
2. **人物背景与关键转折**，解释他为什么走到今天；
3. **最近 90 天关键事件**，每条包含本人表达、媒体/社群 framing 和来源等级；
4. **他怎么看自己 vs 外界怎么看他**；
5. **深度画像与三条 Talking Points**，包含可以直接开口的问题；
6. **数据可信度、来源限制和搜索备注**。

每个重要结论都绑定已打开的来源。无法验证的社交媒体具体链接会保留账号主页，并明确标注需要手动定位，不会猜测 URL 或 status ID。

## Mira 运行环境

Mira 是原项目使用的内部 Agent 运行环境。它负责承载 Skill、调度并行研究任务，并提供部分内部工具能力。

这个 Skill 的研究方法已经写在 `SKILL.md` 中，因此在 Codex 或 Claude Code 中可以直接运行。Mira 只是其中一种运行环境；如果某个环境提供更强的 Agent 调度或文档能力，Skill 会使用这些能力，但不会改变研究结构。

原项目中的四路研究可以理解为四个并行角色：

- **自述线**：只看目标人物自己说了什么、做了什么；
- **媒体线**：看媒体和行业报道如何解释这些动作；
- **旁观线**：看社群、从业者和公开讨论如何反应；
- **业务线**：结合会面目的，判断哪些信号值得转化成问题。

如果当前运行环境没有并行 Agent，仍然按同样的四条线顺序完成，不会因为调度能力不足而跳过某一类证据。

## sensight 信源增强层

会前研究里经常遇到一个问题：搜索结果能证明“某人在 X 上讨论过某个主题”，但只能找到账号主页，无法安全地猜出具体 post URL。

sensight 是原内部环境中的实时社交媒体检索服务，用于在信号较新、且账号主页是唯一已验证链接时：

- 拉取目标人物近期公开动态；
- 用关键词检索相关内容；
- 返回真实的内容 URL、原文摘录和发布时间；
- 帮助把账号主页升级为可核验的具体内容链接。

它当前最适合 X/Twitter 的作者动态和语义搜索。其他平台可以作为后续扩展方向。

信源增强的校准规则是：

- 命中目标人物本人发布的内容：可以作为“本人表达”引用；
- 命中第三方发布的内容：不能把它归因给目标人物；
- 没有命中近期具体内容：保留已验证的账号主页，并标注需要手动定位；
- 服务不可用或运行环境不支持：继续使用主研究流程，不阻塞简报生成。

在没有这层增强时，主研究流程仍然使用已经验证的账号主页或文章链接，并在简报中说明具体内容链接需要手动定位。信源增强只改善引用精度，不改变研究结果的主体结构，也不是运行这个 Skill 的硬依赖。

## 设计原则

1. **按时间搜索，而不是按相关性搜索**：旧的成名事件不一定是他现在正在讲的故事；
2. **差异就是信号**：本人叙述、第三方 framing 和社群情绪要放在一起比较；
3. **人物背景写成叙事，而不是简历条目**：重点解释关键转折和底层逻辑；
4. **Talking Points 不是销售脚本**：每条问题都应具体、自然，并且和会面上下文相关；
5. **来源增强优先于来源猜测**：不能验证的链接就明确标注，不编造具体内容 URL；
6. **90 天看叙事弧线，较短窗口看原文证据**：两者服务于不同的研究目的。

## 信息边界

本 Skill 只整理公开信息。它不会访问私密数据，不会推断敏感个人属性，不会把社群单条评论当成事实，也会把事实、来源转述、社群观点和助手推断分开标注。
